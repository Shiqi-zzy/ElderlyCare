## 1. 设计总览与关键决策

### 1.1 现状可复用的基础（避免重复造轮子）



* 平台已有：`institutions`（机构，含 address/contact\_phone/license/is\_verified）、`users`（含 phone、institution\_id、role）、`elderly`（**已有 address 字段但非结构化**）、`authorizations`（人员 - 老人授权）、`work_orders`（含 emergency 类型与状态机）、`audit_logs`、`qualification_reviews`。

* App 本地已有：`organization`（机构，字段极简）、`AppUser`（工作人员，含 organizationId/qualification）、`service_record`（服务记录）、`todo_item`（待办）、`staff_schedule`（排班）、`local_alert`（告警镜像）、`binding_request/user_elderly_binding`（绑定申请 / 关系）、工作人员 "我的" 页 `StaffMyScreen`（**家属 "我的" 要模仿的样式**：渐变信息头 + 指标卡 + 方形宫格 + 条状列表）。

### 1.2 已确认的设计决策（评审已拍板）



1. **两级告警（已确认）**：跌倒瞬间，家属 + 责任社区收正式告警（社区自动生待办），**医院大屏对应社区同步闪红备警**（知道出事、不生成处警任务）；社区点【紧急出警】后医院才生成正式急救事件、值班医生可处警。

2. **严格闭环顺序 + 一条旁路（已确认）**：转警事件必须 "医院完成 → 社区才能完成 → 家属可见"；**未转警的轻微事件允许社区自行闭环**。

3. **医院改绑社区（已确认：多对多 + 管理端审批）**：医院不再直接申请老人，而是申请绑定社区，**由管理端审批**；一家医院可绑多个社区、一个社区也可对接多家医院；绑定后可见该社区下 "已被家属授权给社区" 的老人，平时脱敏、急救 / 值班时开放必要明文。

4. **双轨实现**：三端同在一个 App（切换账号演示），主路径用 App Room 共享 `incident` 表 + Room Flow 实现 "切账号即看到不同视图" 的零延迟虚拟联动；Web 平台侧同步设计云端表与接口，概念与字段保持一一对应。

5. **急救视频临时授权随事件开闭（已确认，最小授权）**：社区点【紧急出警】的瞬间，自动向处警医院的在班医生授予本次事件的临时权限（实时视频 + 告警 + 必要明文）；事件 CLOSED 后自动收回并写审计日志；未转警事件医院不获得任何授权。家属端 "我的医院" 可查每次临时授权的起止记录。

6. **加急 - 升级 - 处罚（已确认，参数：15 秒 × 3 次）**：转警后每 15 秒无人处警加急一次，第 3 次加急后仍无人接 → 自动升级给 "下一个排班人员"，并对**在班却漏接的医生**记一次处罚；无人在班则只升级、不罚医生（排班空缺记为管理问题）。详见 2.5。

### 2.3 incident 状态枚举与按钮权限矩阵



| 状态                     | 含义                 | 家属可见            | 社区可操作                | 医院可操作             |
| ---------------------- | ------------------ | --------------- | -------------------- | ----------------- |
| RAISED                 | 已触发，三方知会           | 告警详情            | 待办出现                 | 大屏社区闪红            |
| COMMUNITY\_RECEIVED    | 社区已接收（自动）          | 进度              | 联系家属记录、【紧急出警】、【自行闭环】 | 仅备警               |
| DISPATCH\_REQUESTED    | 已请求医院出警            | "已呼叫医院"         | 查看等待、**不能完成**        | 出现正式急救事件          |
| URGENT\_x              | 加急中（15s / 次，共 3 次） | 看到加急            | 看到加急、可电话催促           | 在班医生强提醒           |
| ESCALATED              | 3 次加急未接，已升级下一排班人   | 看到 "已升级"        | 看到升级承接人              | 原在班医生记漏接处罚，承接人可处警 |
| HOSPITAL\_ACCEPTED     | 医生已处警（先接先得）        | "医院已出警・医生 X"    | 看到处警人 / 时间           | 其他医生只读            |
| HOSPITAL\_DONE         | 医院已处置完成            | 看到措施摘要          | **【处置完成】解禁**         | 等待社区闭环            |
| COMMUNITY\_DONE→CLOSED | 社区闭环，事件结束          | 看到 "已处置完成"+ 时间线 | 生成社区服务记录             | 归档                |
| SELF\_CLOSED           | 社区自行闭环（旁路）         | 看到结果            | 仅未转警可用               | 不涉及               |

**加急 - 升级 - 处罚规则（已确认：15 秒 × 3 次）**



* T = 社区点【紧急出警】（DISPATCH\_REQUESTED）：记录此刻在班医生集合 on\_duty\_user\_ids，开始倒计时。

* T+15s 无人处警 → urgent\_count=1，全部在班医生强提醒（响铃 + 置顶 + 红色角标）；T+30s → 第 2 次；T+45s → 第 3 次。

* **第 3 次加急后仍无人处警 → 立即 ESCALATED**：按 2.5 规则找 "下一个排班人员" 承接；同时把 on\_duty 中始终未响应的医生写入 missed\_user\_ids，各记一次漏接处罚。

* 倒计时在任一医生 HOSPITAL\_ACCEPTED 时立即停止；演示模式可在设置里把 15s 调小（如 5s）便于答辩演示。

### 2.5 升级顺序与值班处罚机制（新增）

**"下一个排班人员" 的查找顺序**



1. 当天排班表中，当前班次之后**最近一班**的医生（即使其班次尚未开始，也提前呼叫）；

2. 当天无后续班次 → 同医院其他资质 APPROVED 的医生（忽略是否在班）；

3. 仍无人 → 医院管理员 / 机构负责人账号兜底；

4. 全程无人承接 → incident 标记 ESCALATED\_UNANSWERED，社区端看到 "医院无人响应"，可改拨预留电话（不阻断社区自行联系）。

**处罚判定（关键：区分医生责任与排班空缺）**



* **在班漏接（罚）**：转警时在班（on\_duty\_user\_ids 非空）但 3 次加急内未处警 → 每人记 1 次 `missed_response`，绩效 -5 分。

* **无人排班（不罚医生）**：on\_duty 为空，属于排班管理漏洞，只升级并给管理端记一条 "排班空缺" 提醒。

* **升级后仍漏接（加重）**：被升级承接人在其收到后 15s 内仍未接 → 记 `escalation_fault`，绩效 -10 分。

* 实际处警人不罚（无论是否原在班）；多名在班医生中只要 1 人及时处警，其余人不记漏接。

**处罚等级（虚拟，自动累计；参数已确认采用：漏接 -5 分、升级仍漏接 -10 分、初始绩效 100）**



| 滚动周期内漏接次数 | 等级            | 后果（虚拟）                 |
| --------- | ------------- | ---------------------- |
| 第 1 次     | warning 警告    | 系统提示，本人 "我的 - 值班绩效" 可见 |
| 累计 3 次    | notice 通报     | 院内通报记录，管理端可见           |
| 累计 5 次    | suspension 停班 | 自动暂停其排班资格，需管理员恢复       |



* 医生端 "我的" 新增 "值班绩效"：本月在班时长、接警数、平均响应秒数、漏接次数、绩效分、处罚记录；管理端可查看全员排行并手动撤销误判处罚。

* 每次处罚写 audit\_logs，保证可追溯、可申诉撤销。

### 2.4 派单 / 可见性规则



* **社区派单（已确认：8 栋楼、一人可管多栋、暂不共管）**：全小区固定 1~8 栋，网格员注册时从 8 栋中多选负责楼栋；每栋有且仅有一个负责网格员（责任唯一，不做多人共管/抢单），一名网格员可同时负责多栋；告警按老人楼栋精确派给该栋唯一责任人；该栋未分配网格员时挂社区公共池（机构内可见、管理端提示补分配）。旧逻辑说明：替代现在 "派给第一个授权社区人员"。

* **医院可见（多对多）**：医生所属医院经管理端审批 active 绑定老人所属社区（一家医院可绑多社区、一个社区可对接多家医院），且医生资质 APPROVED；新急救事件只推 "当前时间落在班次内" 的医生（先接先得，处警后其余人看到被谁接走）。

* **脱敏口径**：医院平时列表仅显示：姓氏 + 性别 + 年龄 + 楼栋 + care\_level+ 既往大病标签（无姓名全名、无电话、无详细病历、无视频）；处警中 / 急救授权期间开放：全名、家属电话、病史、实时画面（**临时授权随事件开闭**：DISPATCH\_REQUESTED 自动授予在班医生，CLOSED 自动收回并写审计；未转警不授权）。

## 3. 分端改造方案

### 3.1 家属端

**(1) "我的" 页改版（对齐 StaffMyScreen 结构，功能全部为已实现功能的重新组织 + 新增查看类功能）**



* 顶部：浅蓝渐变信息头（家属头像 / 昵称 / 绑定老人数），上浮指标卡（绑定设备数、服务次数、告警数、在管机构数）。

* 中部 "方形功能宫格"（每行 3\~4 个方按钮）：老人档案、我的设备、授权管理、**我的社区**、**我的医院**、**服务记录**、**模拟跌倒（演示）**、隐私设置。

* 下部 "条状列表"：消息通知、帮助与客服、关于我们、退出登录。

* 已实现的档案编辑 / 设备 / 授权 / 隐私 / 客服逻辑全部保留，仅改入口布局。

**(2) 新增 "我的社区 / 我的医院" 详情页**



* 机构基础信息：名称、地址、联系人、电话（注册预留，点击拨号 `ACTION_DIAL`）、服务范围 / 简介、资质状态。

* 对应本老人的**服务记录时间线**（来自 service\_record /incident 汇总：时间、服务人员、类型、内容、时长）。

* 医院页额外显示：合作来源（由哪个社区绑定）、当前 / 历史急救记录、撤回知情入口。

* 待审批的社区 / 医院申请在此显示快捷入口（与授权管理联动角标）。

**(3) 档案地理位置**：向导 / 档案编辑新增 "居住位置"：选择所属社区（机构列表）→ 楼栋（固定 1~8 栋）→ 单元 → 房号；这是社区网格化派单的前提，未填则引导补全。

**(4) 模拟跌倒按钮**：见第 4 节，一键走完整 incident 流程。

**(5) 事件详情 / 时间线**：告警点进去显示三端进度时间轴 + 家属 / 网格员 / 医生电话（详情可拨打）。

### 3.2 社区端

**(1) 注册 / 入驻改造**



* 工作人员注册时先选所属社区（已有机构列表选择；无可 "申请新建社区" 虚拟走管理端审核），再从**固定 1~8 栋中多选负责楼栋**（一人可管多栋，每栋责任唯一、暂不共管，可后续在 "我的 - 个人信息" 调整）。

* 一个社区下可注册多个网格员账号，各自只看 / 申请自己楼栋的老人（申请老人列表按楼栋过滤，非本楼栋置灰）。

**(2) 工作台 "社区大屏"（虚拟地图）**



* 用**楼栋网格示意图**（固定 1~8 栋，4 列 × 2 行方块矩阵，非真实地图）：每栋一个方块，标注楼栋号、负责网格员（唯一）、在管老人数；方块状态：正常（浅绿）、关注（黄）、**有未处置告警时红色闪烁动画**。

* 点楼栋 → 该栋老人列表 + 当前事件；点老人 → 事件详情 / 待办。

* 大屏顶部汇总：今日事件、待出警、处警中、已闭环。

**(3) 待办与处置**



* 跌倒触发后，责任网格员工作台**自动生成待办**（复用 todo\_item，关联 incidentId，高优先级置顶）。

* 待办条目后固定两个按钮：【联系家属】（拨号 + 可填沟通记录）、【紧急出警】（二次确认 → 状态 DISPATCH\_REQUESTED，推绑定医院）。

* 转警后区域实时显示：等待处警 / 已处警（医生名 + 时间）/ 加急中；**【处置完成】按钮在 HOSPITAL\_DONE 前置灰并提示 "等待医院处置完成"**。

* 未转警可【自行闭环】，填收尾说明。

* 闭环后自动写一条社区 `service_record`（含全程时间戳与时长）。

### 3.3 医院端（前台模式）

**(1) 绑定模式改造**



* 移除 "直接申请绑定老人"，改为【申请绑定社区】：选社区 → 填合作说明 → 提交管理端审批（演示可一键通过）→ active 后自动列出该社区全部已授权老人（脱敏，见 2.4）。

* 一家医院可绑多个社区、一个社区可对接多家医院（多对多）；"已绑定社区" 列表可解除。

**(2) 医生注册、排班与值班绩效**



* 前台可注册多个医生账号；资格认定走现有资质流程（演示一键 "虚拟通过"）。

* 排班：周历 / 日期 + 上下班时间（复用 staff\_schedule 扩展，两种模式并存：按周循环的常规排班 + 指定日期的临时排班/调班）；登录后顶部显示 "当前在班 / 未排班"，**仅在班医生接收新急救**；非值班可查历史、不可接新警。

* "我的 - 值班绩效"：本月在班时长、接警数、平均响应秒数、漏接次数、绩效分（初始 100）、处罚记录；漏接按 2.5 自动生成，停班状态下不派新警、需管理员恢复。

**(3) 急救大屏（首页 tab 升级）**



* 上半：**绑定社区网格方块**，某社区有转来的紧急事件时该方块**红色闪烁 + 角标数字**，点击进入事件。

* 下半："近期急救事件" 自动出现社区转来的事件（含社区名、老人脱敏信息、触发时间、等待时长倒计时）。

* 每条事件后【一键处警】：当前在班医生先接先得 → 状态 HOSPITAL\_ACCEPTED，社区端同步看到处警医生；**15 秒未接连续加急（共 3 次，按钮脉冲 + 响铃），3 次后自动升级下一排班人，原在班医生记漏接处罚**；被升级人界面显示 "升级承接" 标识。

* 处置后填 "处置措施"（必填文本 + 可选标签）→【已处置完成】→ HOSPITAL\_DONE，自动写医院 `service_record`；事件关闭时本次急救临时视频授权自动收回。

### 3.4 管理端（Web）



* 社区 / 医院入驻审核、机构信息维护；社区人员 - 楼栋分配、医生 - 排班查看与调整；医院 - 社区绑定审批；全平台 incident 总览（状态 / 时长 / 加急 / 升级统计）；服务记录归档查询；模拟审核一键通过。

* **值班绩效管理**：医生响应率 / 平均响应秒数 / 漏接次数 / 绩效分排行；处罚记录查看、误判撤销、停班人员恢复排班；排班空缺（无人在班却有转警）单独统计，定位管理责任。

## 4. 完整工作流脚本（跌倒场景，演示主路径）

> 入口：家属端 "我的 → 模拟跌倒"（或复用平台 
>
> `/api/alarm/simulate/trigger`
>
> ）。下列每一步标注【写库时间戳】与三端所见。



1. **T0 触发**：生成 local\_alert/alarm + incident (RAISED)，【triggered\_at=T0】。家属收到告警通知；按楼栋匹配网格员，其工作台生成待办，【community\_received\_at=T0】；绑定医院大屏对应社区方块闪红（备警，不生任务）。

2. **T1 社区响应**：网格员打开待办，看到老人基础信息与家属电话，点【联系家属】拨号，可填沟通记录【family\_contacted\_at】。

* 轻微 → 【自行闭环】→ SELF\_CLOSED，写社区服务记录，家属看到结果（流程结束）。

* 严重 → 点【紧急出警】（二次确认）→【dispatch\_requested\_at=T1】，incident 推医院，医院 "近期急救事件" 出现，【hospital\_received\_at=T1】，家属端显示 "已呼叫 XX 医院"。

1. **T2 医院处警**：当前在班医生看到事件（倒计时），点【一键处警】先接先得，【hospital\_accepted\_at=T2、hospital\_user\_id】；社区端变为 "XX 医生已于 T2 出警"，同时为处警医生开通本次事件临时视频 / 明文授权。若无人接：T1+15s 第 1 次加急、+30s 第 2 次、+45s 第 3 次（urgent\_count、urgent\_last\_at），社区端同步看到 "已加急 N 次"；**第 3 次后仍无人接 → ESCALATED（escalated\_at），自动呼叫下一排班医生（查找顺序见 2.5），原在班医生各记一次漏接处罚（missed\_user\_ids、doctor\_penalties、绩效扣分），社区 / 家属端看到 "已升级至 XX 医生"**。

2. **T3 医院完成**：医生填处置措施 →【已处置完成】，【hospital\_done\_at=T3、hospital\_treatment】，写医院服务记录；社区端【处置完成】按钮解禁、家属端看到措施摘要。

3. **T4 社区闭环**：网格员核实 / 收尾，填说明 →【处置完成】，【community\_done\_at=T4、closed\_at=T4】，写社区服务记录；incident=CLOSED；家属端显示 "本次事件已于 T4 由社区处置完成" 及完整时间线。

4. **服务记录**：社区记录（T0→T4 全程、网格员、沟通与收尾）、医院记录（T1→T3、值班医生、处警措施）均可在本人 "服务记录" 和家属 "我的 - 社区 / 医院" 中查看。

## 5. 联动与推送机制



* **单机演示（主）**：三账号共用同一 Room，`IncidentDao` 提供按角色过滤的 Flow（家属看本人老人、社区看本楼栋、医院看绑定社区 + 在班）；任何一端改状态，其余端切到前台即由 Flow 自动刷新，无需服务器。

* **云端（Web / 真机）**：incident 状态变更走平台 WS `/api/ws/live`（需补上 `NotificationService.set_ws_manager` 注入 —— 这是现存断点），消息类型新增 `incident_new / incident_update / incident_urgent`；Web 订阅后局部刷新。

* **加急定时**：演示用 App 内协程定时检查 DISPATCH\_REQUESTED 超时；云端用后端定时任务扫描。

* **电话**：全部来自注册预留字段（users.phone/ AppUser.phone/ FamilyUser），详情页展示并调系统拨号，不做网络电话。
