## 3. 应急事件状态机（仓库层强校验，非法流转直接抛错）



```
RK3 跌倒触发 RAISED

&#x20; └─(自动) COMMUNITY\_RECEIVED  社区网格员收到 + 自动生成待办

&#x20;      ├─ 联系家属 contactFamily

&#x20;      ├─ 自行闭环 SELF\_CLOSED（误报/小事，无需医院）

&#x20;      └─ 紧急出警 requestDispatch → DISPATCH\_REQUESTED（绑定医院唯一时自动选中）

&#x20;            └─ 每 15s 调度器 tick：第 1/2 次 URGENT 加急（在班漏接 -5）

&#x20;                  └─ 第 3 次：ESCALATED 升级下一排班医生（原在班责任人 -10），

&#x20;                       无下一班 → ESCALATED\_UNANSWERED（无人在班不罚医生，只记排班空缺）

&#x20;            └─ 医生 acceptByDoctor 先接先得（单条 CAS UPDATE，并发安全）→ HOSPITAL\_ACCEPTED

&#x20;                  └─ hospitalComplete（处置措施必填）→ HOSPITAL\_DONE

&#x20;                       └─ communityComplete（强校验医院已完成）→ CLOSED
```



* **完整时间链**：raised /communityReceived/familyContacted /dispatchRequested/hospitalAccepted /hospitalDone/closed 各自时间戳；社区、医院各写一条服务记录（含开始 + 完成时间、处置人、处置措施）。

* **闭环顺序强约束**：只有医院 `HOSPITAL_DONE` 后社区才能 `CLOSED`；家属端时间线实时展示全链状态。

* **大屏闪红口径（R1 修正）**：


  * 社区网格大屏：事件未到终态（非 CLOSED / SELF\_CLOSED）对应楼栋就高亮 —— 社区需全程跟到闭环；

  * 医院急救大屏：**仅在等待医院阶段**（DISPATCH\_REQUESTED / URGENT / ESCALATED / ESCALATED\_UNANSWERED）对应社区方块闪红，医生一键处警或处置完成后立即停止闪红。

### 处罚与绩效（与决策一致）



* 初始 100 分；在班漏接 -5、升级承接失败 -10；累计 3 次院内通报、5 次暂停排班；

* 事发时无人在班不罚医生，只记排班管理问题；医生绩效页可看分数 / 处警数 / 漏接 / 处罚明细。
