# Silver Voices5（萤视 Pro 智慧养老）四端联动工作流程深度梳理

> 本文基于 `backend/`、`app/`、`web/` 源码逐文件探查整理，所有功能、端点、阈值、状态机均来自现有代码，未作臆测。
> 探查范围：Android（Kotlin/Compose，包名 `com.elderlycare.app`）119 个 UI/数据文件、Python FastAPI 两套后端共 30+ 路由/服务文件、Web 四端口前端。

---

## 0. 一句话总览

系统以**老人家中的 RK3 适老桌面机器人（萤石摄像头/音箱一体设备）**为物理感知与交互底座，以**两套后端 + 萤石开放平台云**为枢纽，向上同时服务 **家属端、社区端、医院端、管理端** 四个端口：家属是老人数据的"所有者和授权人"，社区/医院必须经家属授权后按"最小必要"看到不同切面的数据，管理端只做平台治理不接触老人明细；任何一端对老人/设备的操作，都会通过授权关系、WebSocket、工单、消息、设备播报等机制在其余端产生确定性联动。

## 1. 总体架构

### 1.1 "四端"与作为底座的第五端（设备端）

| 端 | 载体 | 入口 | 角色定位 |
|---|---|---|---|
| **家属端 family** | Android App + Web 看板 | App 门户选择页 / Web `family` 门户 | 老人数据所有者：视频、医疗、告警全量可见，且是唯一的授权审批人 |
| **社区端 community** | Android App + Web | 同上 | 日常照护/巡检/随访方：只看告警与脱敏台账，无视频无病历 |
| **医院端 hospital** | Android App + Web | 同上 | 诊疗方：只看医疗档案，可录入诊疗/建议/复诊提醒，急救时可"破窗" |
| **管理端 admin** | **仅 Web** | Web `admin` 门户 | 平台治理：资质审批、统计、审计、权限过期处理、AI 分析，不直接看老人明细 |
| **老人设备端（底座）** | RK3 适老桌面机器人（萤石设备） | 家中硬件 | 感知（摄像头/传感器/AI）+ 交互（通话、TTS 播报、留言、点播广播） |

- App 端门户选择页 `PortalSelectionScreen.kt` 只有**家属/社区/医院三个入口**（管理端无 App）；登录后分别进入 `FamilyNavGraph`、`CommunityNavGraph`、`HospitalNavGraph` 三套独立底部导航。
- Web 端 `portal_router.js` 有**四个门户**（家属/社区/医院/管理员），对接平台后端。

### 1.2 两套相互独立的后端（重要）

`platform_main.py` 文件头明确说明项目存在**两套 FastAPI 后端**：

| 后端 | 入口/端口 | 服务对象 | 职责 |
|---|---|---|---|
| **ERTC 信令后端** | `main.py`，`:8000` | Android App ↔ RK3/萤石云 | 云通话信令、萤石回调、抓拍、留言、档案云同步、智能体知识库、设备告警 WS |
| **四端平台后端** | `platform_main.py`，`:8002` | Web 四端口前端 | 用户/老人/授权/告警/工单/健康档案/急救/资质/统计/审计，平台 WS |

此外还有第三条"通道"——**RK3 局域网 HTTP 服务 `:8080`**（无公网 IP，仅手机与设备同一 WiFi 可达），供家属端拉取实时/周/年健康报告。

### 1.3 通信与存储通道总览

| 通道 | 协议/端点 | 用途 |
|---|---|---|
| 萤石开放平台云 | EZOpenSDK / ERTC / v3 clock 闹铃 / 云广播 | 直播预览、回放、双向音视频、设备 TTS 闹铃、音频广播、设备视频留言 |
| 信令后端 WS | `WS /api/ws?clientId=xxx` | App 接收设备来电、通话状态、设备告警、抓拍图片更新；客户端可发 `{"type":"subscribe","sns":[...]}` 订阅授权设备 |
| 平台后端 WS | `WS /api/ws/live` | Web 四端接收告警/工单/急救/授权等业务推送 |
| 平台 REST | `/api/auth /family /community /hospital /admin /alarm /work_order` 等 | 四端 Web 业务 |
| 信令 REST | `/api/rtc/* /api/ezviz/* /api/leave-message/* /api/captures /api/health-profile/*` | App 设备业务 |
| RK3 局域网 | `http://<设备IP>:8080` | 健康实时/周报/年报/AI 建议、点播与 FM 控制 |
| App 本地 Room | SQLite（端内） | 档案、绑定/授权申请、消息、提醒计划、抓拍、健康建议（离线可演示链路） |
| 平台数据库 | `backend/data/elderly_care.db`（13 张表，启动幂等建表+种子数据） | Web 云端业务的唯一事实源 |

> **注意（两套实现的关系）**：App 内用 Room 实现了一套完整的"绑定申请→家属审批→授权生效→按 SN 过滤数据"链路；Web 端用平台 SQLite + `authorizations` 表实现了同一概念的云端版本。二者概念对齐、数据模型平行，分别支撑 App 演示与 Web 平台，本文第 8 节会分别标注。

## 2. 老人设备端（RK3 适老桌面机器人）能力

RK3 是四端联动的数据源头与老人侧执行器，一台设备对应一份老人档案（`Step7DeviceBinding.kt`："一台机器人对应一份档案"）。

**感知与上报**
1. 摄像头视频流（经萤石云供家属直播/回放，云台 PTZ 可控）。
2. AI 事件检测：跌倒、长时间静止、离床、烟雾、燃气、生命体征异常等，经萤石云以 webhook 回调后端（告警类型常量见 `config.py`：`fall/stillness/smoke/gas/door_open/bed_absence/vital_sign`）。
3. 本地健康/情绪 AI 分析，经局域网 `:8080` 提供：实时指标（`/api/health`）、周报（`/api/reports/weekly`）、年报（`/api/reports/yearly`）、给家属的 AI 建议（`/api/suggestions/latest`）。

**交互与执行（被动接收各端下发）**
1. **双向音视频通话**（ERTC）：可主动呼叫家属（设备上一键呼叫），也可被家属呼入。
2. **TTS 语音播报**：家属文字留言、家属提醒计划、医院复诊提醒，均通过萤石 v3 clock 闹铃接口下发到设备本地合成播报。
3. **音频播放**：家属录音留言、云广播、戏曲/电台点播（FM）。
4. **视频留言录制**：老人在设备上录的视频留言，由 App 经 SDK 拉取（近 7 天、direction=1、contentType=2 的视频）。
5. **自动抓拍**：告警瞬间图片回传（加密图用绑定时上报的 6 位设备验证码解密）。

## 3. 家属端功能（App 为主，Web 为辅）

### 3.1 Android App —— 五个 Tab（`FamilyNavGraph.kt`）

**① 首页 home（`FamilyHomeScreen.kt` + `HomeBusinessCards.kt`，8 个业务入口）**

| 入口 | 实现链路 | 说明 |
|---|---|---|
| 抓拍 | `/api/ezviz/capture` 云端抓拍 + SDK 本地抓帧 `/capture/upload` | 4 秒限流防连点；手动/自动抓拍统一进"全部抓拍" |
| 视频通话 | `/api/rtc/token` → ERTC 房间 → `VideoCallScreen` | 双向音视频：麦克风/扬声器/摄像头开关、前后切换、挂断 |
| 对讲（直播预览） | EZOpenSDK 直连萤石云 `LivePreviewScreen` | 实时画面 + 云台 PTZ 控制（`PtzControlDial`） |
| 录像回放 | `PlaybackScreen` 云存储回放 | 按时间轴回看 |
| 留言 | 文字/录音/视频留言（见 §8.5） | 文字走设备 TTS，录音走双通道下发 |
| 录音 | `RecordOverlay` 录制后下发 | 语音留言 |
| 点播 | `Rk3PlayScreen`（RK3 局域网/`Rk3MediaRepository`） | 远程控制设备播放曲目 |
| 广播 | `Rk3FmScreen` 云广播/FM | 电台/广播控制 |

**② 日程 calendar（`CalendarScreen` + `reminder/` 包）**
- 提醒计划列表/日历/表单/详情：单次、每日、每周重复；可选播报音色（`VoiceSelectScreen`，手机端 edge-tts 试听）。
- 保存后经萤石 v3 clock 下发到 RK3 到点 TTS 播报；后台轮询 schedule/record 识别"已播报"，回写一条系统消息，播报后清理设备残留闹铃。

**③ 报告 reports（`ReportsScreen.kt`，四 Tab：实时/周度/年度/建议）**
- 数据源为 RK3 局域网 `:8080`（服务器地址在"我的→客服与设置"配置）；为空/不通/跨网时友好降级不崩溃；含折线图、指标环等图表组件。

**④ 消息 messages（`message/`、`messages/` 包）**
- 消息中心 `MessageCenterScreen`：家属与设备的留言会话、设备视频留言播放、系统提醒、**医生健康建议独立气泡（MSG_TYPE_ADVICE）**、**萤石设备告警消息（messageCategory=2 报警）**、绑定申请消息（带未读角标）。
- 全部抓拍 `AllCapturesScreen`、告警中心 `AlertCenterScreen`。

**⑤ 我的 my（`MyScreen.kt`）**
- 老人档案建档/编辑（7 步向导向导见下）、绑定设备状态、**授权管理（审批社区/医院申请、解除授权）**、客服与设置（含 RK3 服务器地址配置）、隐私协议、退出登录。

**建档向导（`FamilyWizardScreen` + `wizard/steps/`，7 步）**
1. 基本信息 → 2. 生活方式 → 3. 病史 → 5. 体检数据 → 6. 兴趣爱好 → 7. 设备绑定（`Step7DeviceBinding`）。
- 第 7 步：SN 扫码/手动输入 + 设备标签上的 **6 位大写验证码** → 先调萤石 SDK `addDevice` 校验 → 再 POST `/api/device/auth` 上报后端（后端据此解密告警加密图）；**后端同步不成功则阻断向导"完成"按钮**，可"重试同步"（幂等 upsert）。
- 档案同时本地 Room 保存 + POST `/api/health-profile/upload` 云同步，并异步同步到萤石智能体知识库（供设备 AI 对话使用老人画像，失败降级不阻断）。
- 向导内置隐私合规三条声明：病历等敏感数据只存自研后端、不上萤石云；萤石仅收脱敏情绪分值/活动统计；可随时撤回授权、删除后 7 日销毁。

### 3.2 Web 家属看板（`/api/family/*`，`family_dashboard.js`）

- 我的老人：建档（POST `/elderly`）、列表、详情、编辑。
- 设备：查看设备列表、更新直播流地址、**生成 6 位设备绑定码**（供社区/医院扫码/输码绑定设备）、作废绑定码。
- 告警：查看本人老人告警、详情、**确认告警 acknowledge**、模拟触发（`/api/alarm/simulate/trigger`，演示用）。
- **授权管理（核心）**：查看授权列表、主动授予授权（grant：权限类型 + data_scope + 有效期）、审批收到的绑定申请（approve/reject）、撤销授权（revoke）。
- **隐私控制**：暂停监控（`/monitoring/pause`）/恢复监控（`/monitoring/resume`）、查看隐私状态。
- 健康档案：查看 `visibility=both` 的诊疗记录（医院录入、对家属可见部分）。

## 4. 社区端功能（App + Web）

### 4.1 Android App —— 五个 Tab（`CommunityNavGraph.kt`）

**① 工作台 dashboard（`CommunityDashboardScreen.kt`）**
- 今日概览：服务老人数、待处理事项、重点关注数、服务完成率；待办列表（上门随访/电话随访/健康随访/告警处置）；"全部待办"页；点击进入老人详情。

**② 台账 roster（`CommunityRosterScreen.kt`）**
- 仅展示**已有 ACTIVE 绑定授权**的照护对象花名册（"仅展示您已获授权访问的照护对象"，无授权时引导去资质页发起申请）；点击进入 `UserDetailScreen`：基本信息、健康档案、设备状态、云端健康档案卡。

**③ 告警 alarm（共享组件 `StaffAlarmScreen.kt`）**
- 按 `AuthorizedSnsProvider` 计算出的"本人授权设备 SN 集合"过滤萤石云告警（云端按 AppKey 全量返回、无 SN 参数，故端上过滤）；可"标记已处理"；`CommunityAlertPlaybackScreen` 查看告警关联回放。

**④ 资质 qual（`QualificationGate` + `CommunityQualificationScreen` + 绑定三件套）**
- **资质门**：未登录/未通过资质认证时拦截一切业务功能。
- 提交社区资质材料、查看审核状态。
- **发起绑定申请**（`StaffBindingApplyScreen`）：选择老人 → 查看其档案/设备 → 填写申请说明 → 生成 PENDING 申请 → 家属端"授权管理"收到待审批项。
- `StaffBindingPanels`：我的申请（状态跟踪）、已绑定用户（解绑）。

**⑤ 我的 my（`CommunityMyScreen` / 共享 `StaffMyScreen`）**

**扩展业务页**
- 随访计划 `FollowUpPlanScreen`：添加随访、完成标记；**完成随访自动写服务记录并生成/完成待办**。
- 服务记录 `ServiceRecordScreen`、排班 `StaffScheduleScreen`。
- 工单中心 `CommunityWorkOrdersScreen`：**接单 → 完成流转**（对应平台工单状态机）。
- 社区健康档案 `CommunityHealthRecordsScreen`（脱敏视图）。

### 4.2 Web 社区端（`/api/community/*`）

- 工作台 dashboard 统计、老人列表（**脱敏**）。
- 发起授权申请、查看本人申请状态。
- 6 位设备码绑定设备、查看老人设备。
- **设备巡检**：提交巡检记录（类型：日常/维修/紧急；结果：正常/关注/故障）、查看维保记录、我的维保任务。

## 5. 医院端功能（App + Web）

### 5.1 Android App —— 五个 Tab（`HospitalNavGraph.kt`）

**① 急救面板 emergency（`HospitalEmergencyPanelScreen.kt`，急救大屏风格）**
- 重点患者列表、待响应急救事件、近期急救事件、健康状态分布（正常/关注/异常）统计、服务患者数；患者详情；`HospitalAllEventsScreen` 全部急救事件；`HospitalEmergencyVideoScreen` 急救视频查看（需急救授权，见 §8.7）。

**② 健康档案 records（`HospitalHealthRecordsScreen.kt`）**
- 授权患者列表 → `UserDetailScreen`；`HospitalReportScreen` 录入诊断报告。

**③ 告警 alarm（`StaffAlarmScreen`）**：与社区同一组件，按授权 SN 过滤。

**④ 资质 qual**：同社区——资质门、医院资质提交（执业许可等）、绑定申请/我的申请/已绑定。

**⑤ 我的 my（`HospitalMyScreen`）**

**医院特色业务**
- **健康建议录入**（`HealthAdviceScreen.kt`）：写建议 → ①存本地 `health_advice` 表；②给家属消息中心落一条 `MSG_TYPE_ADVICE` 独立气泡。代码明确约束：**健康建议不走设备播报**（不调闹铃/语音接口），仅 App 内查看；老人未绑设备则只存不推消息。
- **复诊提醒**（`HospitalMedicalRemindScreen.kt`，双路径 + 强制授权校验）：
  - 表单：日期/时间 + ≤20 字内容 + 复选框"下发设备进行播报"。
  - **无 ACTIVE 医院授权 → 复选框置灰**（提示"暂无家属授权"）；有授权但老人未绑设备 → 置灰（提示"未绑定设备"）。
  - 勾选（source=2）：复用家属提醒计划的萤石 v3 clock 通道下发 RK3 播报，但要先走**家属双重确认**（状态 `CONFIRM_PENDING/AGREED/REJECTED`，家属在提醒计划页同意后才真正下发）；不勾选（source=1）：仅 App 本地通知，不调萤石。
- 随访 `MedicalFollowUpScreen`、随访工单 `HospitalFollowUpOrdersScreen`。

### 5.2 Web 医院端（`/api/hospital/*` + 健康档案路由）

- 工作台 dashboard、授权患者列表、授权申请、6 位码设备绑定。
- **急救**：POST `/emergency/request` 发起 24 小时临时监控权限、GET `/emergency/status` 查状态、`/license/renew` 执业执照续期。
- **健康档案录入**（`health_record.py`，全路径路由）：POST `/api/hospital/health/{elderly_id}/add`，类型含诊断、处方、检查报告、用药记录、疫苗；可见性 `visibility=both`（家属也可见）或 `hospital`（仅医院）；GET 拉取本人录入记录。家属侧经 GET `/api/family/health/{elderly_id}` 只看到 both。

## 6. 管理端功能（仅 Web，`/api/admin/*`）

管理端受 `ADMIN_NO_ELDERLY_ACCESS=True` 约束：**不直接开放任何老人明细数据**，只做平台治理。

| 区域/单老人统计 | `/statistics/regional`、`/statistics/elderly/{id}`、`/statistics/alarms` | 区域分布、单人画像统计、30 天告警趋势与 Top 告警老人 |

| AI 服务 | `/ai/fall-risk`、`/ai/health-trend`、`/ai/health-report/{id}`、`/ai/behavior/sleep`、`/ai/behavior/activity`、`/ai/behavior/anomaly/{id}` | 跌倒风险评分、健康趋势、单人健康报告、睡眠/活动行为分析、行为异常识别 |

## 7. 角色权限矩阵 —— 四端数据可见性的总开关

来自 `backend/app/core/permissions.py` 的 `ROLE_DATA_SCOPE`（硬编码权威矩阵）：

| 角色 | 视频 video | 病历 medical | 告警 alarm | 数据是否脱敏 | 说明 |
|---|---|---|---|---|---|
| 家属 family | ✅ | ✅ | ✅ | 否（全量） | 数据所有者，唯一授权审批人 |
| 社区 community | ❌ | ❌ | ✅ | 是 | 只收告警做照护处置，看不到视频和病历 |
| 医院 hospital | ❌ | ✅ | ❌（急救破窗时临时✅） | 是 | 只看病历做诊疗，平时不收告警推送 |
| 管理 admin | ❌ | ❌ | ❌ | — | 只治理，不碰老人明细 |
| 急救临时授权 emergency_monitoring | ✅ | ❌ | ✅ | — | 医院破窗，24 小时失效，data_scope=`{"video":true,"alarm":true,"medical":false}` |

权限校验逻辑：家属直接校验"是否为该老人的 binding_family_user_id"；社区/医院必须存在一条 `authorizations` 记录满足——授权对象是本人、状态 active、未过期，且本次访问类型（video/medical/alarm）落在 data_scope 内，否则拒绝。App 端由 `AuthorizedSnsProvider` 用同一思想实时计算"可访问设备 SN 集合"，**解除授权（REVOKED）后该集合立即缩小，告警列表/消息落库/WS 订阅全部同步收回**。

## 8. 八大联动链路（核心）

### 8.1 链路 A：建档与设备绑定（一切联动的前提）

```
家属 App 7 步向导
  → 本地 Room 落档案
  → 输入设备 SN + 6 位验证码
      → 萤石 SDK addDevice 校验（设备真实存在且验证码正确）
      → POST /api/device/auth 上报 SN+验证码（信令后端保存，用于解密告警加密图）
  → POST /api/health-profile/upload 云端档案
      → 异步 /debug/bindKnowledge 同步老人画像到萤石智能体知识库（失败仅降级）
  → elderly.binding_family_user_id = 家属（平台侧归属关系，后续授权/急救/推送都以此找家属）
```
社区/医院侧另有"6 位设备码绑定"：家属在 Web 生成一次性设备码 → 机构端输码绑定设备（`/device/bind`、`/device/{id}/generate-code`）。

### 8.2 链路 B：授权绑定（机构申请 → 家属审批）

**App 本地版（Room）**
```
社区/医院 StaffBindingApplyScreen 选老人+填申请说明
  → binding_requests(PENDING)，家属"我的"出现未读角标
  → 家属 AuthorizationManagementScreen：
       待处理申请：同意 approve / 拒绝 reject
       当前授权(ACTIVE)：可解除授权 revoke（档案与设备数据不删除）
       授权历史(REVOKED)：只读
  → ACTIVE 后 AuthorizedSnsProvider 立即把该老人设备 SN 纳入机构可见集合
```
**Web 云端版（平台 SQLite `authorizations`）**
```
机构 POST /api/{community|hospital}/authorization/request
  → 家属 GET /api/family/authorization/requests 看到待审批
  → approve / reject；家属也可主动 grant（指定 permission_type、data_scope、effective_until）
  → active 授权即权限矩阵放行依据；到期 → expired；revoke → revoked（均留审计）
```
授权类型包括：告警查看、视频监控（alarm_video/monitoring）、健康档案（health_records）、全量（all）、急救监控（emergency_monitoring）。

### 8.3 链路 C：告警联动闭环（系统最核心链路，双通道）

系统存在**两条互补的告警链路**：

#### 通道①：萤石设备实时链路（App 侧，毫秒级来电式提醒）
```
RK3/传感器检测到异常
  → 萤石云 → POST /api/ezviz/webhook（信令后端）
      ├─ ys.open.rtc.call：设备来电/通话状态（见链路 D）
      └─ 告警类型（_ALARM_TYPES）：
           1) 立即入库 captures（图片 URL 先空着），messageId 幂等去重
           2) WS send_alarm(deviceSerial) 精准推送——只发给"订阅了该 SN"的在线客户端
              · 家属连接后订阅本人设备 SN
              · 社区/医院订阅 ACTIVE 绑定的设备 SN（医院端默认发空列表，不订阅，靠 60s 轮询兜底）
           3) 2 秒内给萤石回 200 + messageId（否则萤石重推）
           4) 异步下载告警图：加密图用 /api/device.auth 保存的验证码解密为 JPEG
              → 落盘 media → 回填记录 → 再推一条 captureUpdated 通知 App 刷新图片
  → App 收到后落 Room 消息（报警类）+ 告警列表/全部抓拍/消息中心可见
```

#### 通道②：平台 AI 分级链路（Web 侧，带防误报与自动派单）
```
AI 异常（admin /ai/* 或设备上报） 
  → AlarmService.create_from_anomaly
  → AntiFalsePositiveEngine 三级防误报评估：
```
**三级防误报（`anti_false_positive.py`，阈值来自 `config.py`）**

- 一级·置信度阈值：烟感/燃气传感器硬触发直接 HIGH；跌倒置信度 < **0.65** 判 LOW 丢弃，≥ **0.85** 判 HIGH，其余 MEDIUM 进二级；静止 ≥0.8 判 MEDIUM，否则 LOW。
- 二级·多帧/历史复核：最近 5 条中同类告警 ≥ **3 次** → 升 HIGH（高可信）。
- 三级·边界升级：跌倒置信度 ≥ **0.9** → EMERGENCY；烟感/燃气 → EMERGENCY。

**四级分级与差异化推送**

| 级别 | 推送家属 | 推送社区 | 推送医院 | 是否自动建工单 |
|---|---|---|---|---|
| LOW | ❌ 仅留存 | ❌ | ❌ | ❌ |
| MEDIUM | ✅ | ❌ | ❌ | ❌ |
| HIGH | ✅ | ✅ | ❌ | ✅（high 优先级） |
| EMERGENCY | ✅ | ✅ | ✅ | ✅（urgent 优先级） |

**自动派单规则（`WorkOrderService.auto_create_from_alarm`）**：HIGH/EMERGENCY 告警自动生成处置工单，优先指派给"已 active 授权该老人且未过期的第一个社区人员及其机构"；无人授权则工单 pending，等待管理员手动派单。工单标题按类型生成（跌倒告警处置、燃气泄漏处置等）。

**告警与工单状态机（双向联动）**
```
告警：active ──家属 acknowledge──▶ acknowledged ──▶ processing ──▶ resolved ──▶ archived
工单：pending ──社区 accept──▶ accepted ──start──▶ in_progress ──complete──▶ completed
                                                          │
                          工单 complete 时自动 resolve 关联告警（"工单 xxx 已完成"）
```
- 家属可在 Web 确认（acknowledge）告警；社区在工单中心接单/开始/完成，**工单一完成，关联告警自动闭环**。
- 全流程经 `AuditService` 留痕：alarm_create（操作人 ai_engine）、alarm_acknowledge、work_order_auto_create（system）、work_order_accept/complete、alarm_resolve。
- 推送经 `NotificationService` 按 push_family/community/hospital 标志，沿平台 WS `/api/ws/live` 找到对应角色/授权关系人精准下发。

### 8.4 链路 D：ERTC 双向音视频通话

**家属呼出**
```
App（首次）POST /api/rtc/setup：一次性开通设备音视频能力 + 建立联系人关联
App POST /api/rtc/token：后端向萤石换取同一房间的 client_token + device_token + roomId
  → ERTC 入会 + inviteDeviceEnterMeeting 呼叫设备
  → VideoCallScreen 双向音视频（远端全屏 + 本地小窗， mic/扬声器/摄像头/前后切换/挂断）
  → /api/rtc/call、/reject、/cancel 控制呼叫状态
```
**老人呼入（设备主动呼叫）**
```
老人在 RK3 上点呼叫 → 萤石 ys.open.rtc.call(action=request) → webhook
  → WS broadcast incoming_call → App 全屏来电界面
  → 后续 action（cancel 取消/reject 拒接/busy 忙线/bellTimeout 超时无人接/answer 接听）
    经 call_state 实时更新界面
```
直播预览与云回放不经自家后端，App 用 EZOpenSDK 直连萤石云。

### 8.5 链路 E：留言·提醒·关怀下发（六种通道对比）

| 业务 | 发起端 | 通道 | 设备侧表现 | 回流/联动 |
|---|---|---|---|---|
| 文字留言 | 家属 | 萤石 v3 clock 单次闹铃（+1 分钟，内容 ≤20 字）；另有 `/api/leave-message/text`（edge-tts 合成后云广播）与 `/tts-preview` 手机试听 | TTS 朗读 | 90 秒后自动删除临时闹铃 |
| 录音留言 | 家属 | **双通道并行**：SDK videotalk 语音通话通道 + 云广播 upload/send；全失败降级 sendonce（WAV→ADTS AAC，multipart 一次性播放） | 播放语音 | 任一通道成功即可，可重发 |
| 视频留言（设备→家属） | 老人 | App 经 SDK 拉取近 7 天 direction=1/contentType=2 视频 | — | 下载入库，`DeviceVideoPlayerScreen` 播放 |
| 提醒计划 | 家属 | v3 clock 周期闹铃 | 到点 TTS | 轮询播报记录→回写系统消息→清理残留闹铃 |
| 复诊提醒 | 医院 | source=1 仅 App 本地通知；source=2 走 v3 clock，**先经家属双重确认（待同意/同意/拒绝）后才下发** | 到点 TTS | 强制 ACTIVE 授权+已绑设备校验，列表显示双重确认徽标 |
| 健康建议 | 医院 | **不下发设备**，写 health_advice 表 + 家属消息中心 MSG_TYPE_ADVICE 气泡 | 无播报 | 家属 App 内阅读 |
| 点播/FM/云广播 | 家属 | RK3 局域网 / Rk3MediaRepository / 云广播接口 | 播放戏曲电台 | — |

### 8.6 链路 F：健康档案联动（双向流动）

```
                ┌── 家属建档（App 7 步）── Room + /api/health-profile/upload ──┐
老人健康数据 ──┤                                                              ├──▶ 萤石智能体知识库（设备 AI 对话用画像）
                └── RK3 本地 AI ──局域网:8080 实时/周/年报告 + 家属建议 ──▶ 家属报告页（图表）

医院 Web 录入诊疗（诊断/处方/检查/用药/疫苗，带 visibility）
  ├── visibility=both     ──▶ 家属 Web/App 可见（GET /api/family/health/{id}）
  └── visibility=hospital ──▶ 仅医院可见
  ── App 机构端 UserDetailScreen 经权限校验后拉云端档案，展示"云端健康档案"卡
```

### 8.7 链路 G：急救破窗（先放行、后审计）

```
医院 Web 选老人 + 填急救理由 → POST /api/hospital/emergency/request
  → EmergencyService 直接写入一条 24 小时 active 的 emergency_monitoring 授权
    （data_scope: video=true, alarm=true, medical=false；grantor 记为该老人绑定家属）
  → 审计 emergency_access_granted（谁、对哪位老人、什么理由、何时到期）
  → WS 立即通知家属："医院已发起 xx 的急救 24 小时临时监控权限，理由：…"
  → 24 小时内医院可看视频/告警/急救面板与急救视频；到期自动失效
  → 重复申请直接返回 already_active，不重复授权
```
注意：这是**"破窗"机制而非家属事前审批**——抢救场景先开通、同步告知家属、全程留痕可事后追责。App 医院端急救面板（重点患者/待响应事件/健康分布）与 Web 状态查询（`/emergency/status`）配套。

### 8.8 链路 H：隐私控制与审计治理

- **家属随时可暂停/恢复监控**（`/api/family/monitoring/pause|resume`、`/privacy/status`）；他人开始查看监控时通过 `notify_monitoring_access` 通知家属本人。
- **授权可随时撤回**：App 解除授权后 SN 集合实时收缩；Web revoke 后权限矩阵立即拒绝；档案与设备数据保留不删，删除档案则 7 日彻底销毁。
- **资质前置**：社区/医院必须先通过资质审核（状态 pending→auto_passed/auto_failed→approved/rejected），App 端 `QualificationGate` 与 Web `/api/auth/verification/*` 双重拦截，管理端审批。
- **全量审计**：告警产生/确认/解决、工单自动生成/接单/完成、授权授予/撤销、急救破窗、设备巡检等全部写 `audit_logs` / 访问记录，管理端可查；管理端还可批处理到期权限。

## 9. 关键状态机汇总

| 对象 | 状态流转 |
|---|---|
| 绑定申请（App） | PENDING →（家属同意）ACTIVE；（拒绝）REJECTED；ACTIVE →（解除）REVOKED |
| 平台授权 | active / revoked / expired / rejected（带 effective_from~effective_until 有效期） |
| 资质审核 | pending / auto_passed / auto_failed / approved / rejected |
| 告警 | active → acknowledged → processing → resolved → archived |
| 工单 | pending → accepted → in_progress → completed（或 cancelled）；完成自动闭环关联告警 |
| 复诊双重确认 | CONFIRM_PENDING → CONFIRM_AGREED（才下发设备）/ CONFIRM_REJECTED |
| 通话 | request（来电）→ answer 接听 / reject 拒接 / cancel 取消 / busy 忙线 / bellTimeout 超时 |
| 设备 | online / offline / fault / maintenance |

## 10. 五个端到端典型场景时序

**场景 1：老人在家跌倒（EMERGENCY 全链路）**
RK3 识别跌倒（置信度 0.92）→ 萤石云 webhook → 后端立即抓拍入库 + 按订阅 SN 秒级推家属和已授权社区 App；平台 AI 链路三级评估升 EMERGENCY → 同时推家属/社区/医院 → 自动生成 urgent 工单派给签约社区 → 家属 App 收到报警与图片、可一键视频通话查看；社区接单→上门→完成工单，告警自动 resolved；管理端留下完整审计。

**场景 2：家属给老人发语音**
家属 App 录音 → videotalk 与云广播双通道下发（失败降级一次性播放）→ RK3 播放；若发文字则建 1 分钟后的单次闹铃由设备 TTS 读出，播完自动删除。

**场景 3：社区想服务一位新老人**
社区 App 资质门通过后，在绑定申请里选老人、写说明 → 家属"我的"页亮角标 → 家属在授权管理点"同意" → 社区台账立刻出现该老人、告警订阅立刻包含其设备 SN；家属随时可"解除授权"，该老人和设备告警即时从社区侧消失。

**场景 4：医院急诊接诊一位院外老人**
医院在 Web 发起急救申请并填写理由 → 系统直接开通 24h 视频+告警权限、同步推送告知家属、记审计 → 医院急救面板看实时画面与事件 → 24h 后权限自动失效。

**场景 5：医院给老人下复诊提醒**
医生在医院 App 建复诊提醒，勾选"下发设备播报"→ 因需家属确认，提醒先到家属提醒计划页显示"待同意"→ 家属同意后经 v3 clock 下发 RK3 → 到点设备语音提醒老人复诊，医院端列表显示"已播报/已同意"。
